# sybil-fl — Scalable Sybil Detection in Federated Learning

Course project (Cryptography & Network Security, IIIT Kottayam). A single-process
federated-learning simulator that tests whether a **secret, cryptographically generated
random projection** of client updates keeps enough similarity structure to detect colluding
Sybils, compared with the same detector on full-dimensional updates — and how much keeping
the projection key secret protects the detector against an adaptive attacker.

> Research prototype. Not a production defence and not a cryptographic proof —
> see `docs/DECISIONS.md` (D2 threat model, D3 projection construction, D4 key handling,
> D10 attacker model) for what is and is not claimed.

## Setup (Windows, CPU)

```powershell
cd sybil-fl
setup_windows.bat            # one click: .venv, CPU torch, package, E0 check, tests
# or manually:
python -m venv .venv
.venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu   # CPU build first
pip install -e ".[dev,plots]"
```

On Linux/macOS, activate with `source .venv/bin/activate`; the rest is the same.

## Commands

```bash
pytest                                                    # full test suite
python experiments/run_central.py                         # E0: downloads MNIST, central sanity check
python experiments/run_main.py --config configs/smoke.yaml        # 3-round smoke test
python experiments/run_main.py --config configs/label_flip.yaml   # one attacked run (8 pool Sybils, 7 -> 1)

# the full study (about 1.5-2 h on a 16-core CPU)
python experiments/run_suite.py --group tune              # seed 0, shadow scoring
python experiments/tune_thresholds.py                     # -> configs/tuned_thresholds.yaml
python experiments/run_suite.py --group e2 --workers 6 --threads 2
python experiments/run_suite.py --group e3 --workers 6 --threads 2
python experiments/run_suite.py --group e6 --workers 6 --threads 2
python experiments/run_scalability.py                     # E5, run on an otherwise idle machine
python experiments/summarize.py                           # -> results/summary/
python experiments/make_plots.py                          # -> plots/
```

The server key comes from `SYBIL_FL_KEY` (64 hex characters) or is generated fresh for each
run; only its source (`env` / `generated`) is recorded. Set it to make a run bit-reproducible.


## Security assumptions (short)

The server is trusted and holds a 32-byte master key `K`; the adversary controls the Sybils,
knows the algorithm and all public parameters, but not `K`, and sees no detection feedback.
Each round's projection matrix is derived as `K_t = HKDF-SHA256(K, info = "sybil-fl|projection|v1|round=t")`
and `R_t = ±1/√k` signs read from `SHAKE-256(K_t || shape label)`. Under the standard PRF
assumptions on HMAC-SHA256 and keyed SHAKE-256, `R_t` is computationally indistinguishable
from random without `K` and independent across rounds. That removes one attack route
(crafting updates against a known projection, measured in E6); it is not a proof that the
detector resists adaptive attacks. The HKDF → keyed-SHAKE composition is not externally
reviewed. `K` and round keys are never written to results or logs (tested).
